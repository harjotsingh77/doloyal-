# LoyalFlow AI — Deep Vertical Slice Build Plan

## What we're building this session
A **production-grade vertical slice** of the LoyalFlow AI platform: real auth, real multi-tenant isolation, a working dashboard with KPIs computed from real data, full customer management, a loyalty points engine, rewards, and an AI assistant — all wired end-to-end and demoable. Features outside this slice (booking UI, QR check-in flow, marketing campaign builder, admin panel, payments UI, WhatsApp/SMS sending) get data-model + stub treatment so they're extensible later.

## Tech decisions
- **DB:** PostgreSQL (Docker Compose included). Prisma ORM. Single source of truth `schema.prisma`.
- **Auth:** Clerk on web (real). Backend verifies Clerk session JWTs via `@clerk/backend`. **Env-gated mock fallback**: when `CLERK_*` keys are absent, both client and server use a deterministic dev user/tenant so the app runs with zero setup.
- **AI:** OpenAI (real, function-calling) for assistant + retention recommendations. **Env-gated fallback**: rule-based churn/loyalty scoring always runs server-side; if `OPENAI_API_KEY` is missing, the assistant returns structured templated responses built from real DB queries (so it's still useful, just not generative).
- **Multi-tenancy:** Row-level isolation. Every business entity carries `tenantId`. A `TenantContextGuard` resolves the active tenant from the session and a Prisma middleware enforces `tenantId` scoping automatically — no cross-tenant leaks.
- **RBAC:** Roles (Owner/Manager/Receptionist/Staff/Customer) via a `Membership` (user↔tenant) table. Decorators `@Roles()` + `RolesGuard`. Clerk handles identity; we own authorization.
- **Styling:** Tailwind + shadcn/ui, Framer Motion, dark mode, spec colors (#2563EB primary, #60A5FA accent, #10B981 success, #EF4444 danger, #F8FAFC bg). Apple/Linear/Stripe aesthetic: whitespace, rounded-2xl, soft shadows, glassmorphism used sparingly.

## Prisma data model (comprehensive — powers real KPIs + future features)
Core entities (all tenant-scoped unless noted):
- `User`, `Tenant` (Business), `Membership` (user↔tenant+role), `Branch`, `Staff`
- `Customer` (name, phone, email, dob, anniversary, tags, notes, avatar, source, createdAt)
- `Service` (name, duration, price, category, pointsMultiplier)
- `Appointment`, `Invoice` + `InvoiceItem` (subtotal/discount/tax/total/paymentMethod/status)
- `LoyaltyConfig` (per tenant: pointsPerCurrency, mode, expiryDays), `PointsLedger` (immutable, balance-after, expiresAt)
- `Reward`, `RewardRedemption`
- `MembershipTier` (Silver/Gold/Platinum), `CustomerMembership`
- `Referral`, `Campaign`, `Notification`, `Activity` (recent-activity feed), `AuditLog`
- `Subscription` (plan, status, stripeId) — stub for billing

## Backend (apps/api — NestJS)
Modules:
1. **AuthModule** — Clerk JWT verification, `CurrentUser` decorator, dev-user fallback, `TenantContextGuard`.
2. **TenantsModule** — tenant CRUD, onboarding, settings (brand colors, hours, tax).
3. **UsersModule** — memberships, roles, invites.
4. **CustomersModule** — full CRUD, search/filter, CSV import/export, timeline aggregation, LTV calc.
5. **LoyaltyModule** — config, `earnPoints(invoice)`, `redeemPoints(reward)`, manual adjust, ledger history, expiry job hook.
6. **RewardsModule** — CRUD, redemption flow.
7. **MembershipsModule** — tiers CRUD, customer membership assign.
8. **DashboardModule** — aggregates all KPIs (today's revenue/customers, repeat/new/inactive, points redeemed, membership sales, appointments, monthly growth, 30-day revenue + customer graphs, top customers, top rewards, recent activity). Single `GET /dashboard/overview` endpoint.
9. **AiModule** — assistant chat (OpenAI function-calling with tools: `getKpis`, `searchCustomers`, `getRevenueTrend`, `getChurnRisks`, `listInactiveCustomers`, `getTopCustomers`), retention engine (rule-based churn-risk + loyalty-score per customer → AI recommendations + campaign suggestions).
10. **AppointmentsModule / InvoicesModule** — CRUD enough to feed KPIs and loyalty earn.
- Global Prisma service, exception filter, validation pipe, request logging, config module, CORS.
- Seed script generating 1 demo business, staff, ~200 customers with visits/invoices/points over 90 days so dashboards look alive.

## Frontend (apps/web — Next.js 14 App Router)
- **Landing page** (`/`) — hero, features, pricing tiers (Free/Starter/Growth/Pro/Enterprise), CTA. Premium motion.
- **Auth** (`/sign-in`, `/sign-up`) — Clerk hosted components, or mock-auth gate in dev.
- **Onboarding** (`/onboarding`) — multi-step form (business name, category, phone, email, address, logo upload slot, GST, hours, employees, reward prefs) → creates tenant + loyalty config.
- **App shell** (`/app`) — sidebar (Dashboard, Customers, Loyalty, Rewards, Memberships, Referrals, Campaigns, Booking, Staff, Branches, Analytics, AI Assistant, Settings), topbar (tenant switcher, dark-mode toggle, profile), Framer page transitions, loading skeletons. Non-slice routes show polished "coming soon" placeholders.
- **Dashboard** (`/app/dashboard`) — KPI cards (animated count-up), revenue + customer area charts (recharts), top customers table, top rewards, recent activity feed. Real data from `/dashboard/overview`.
- **Customers** (`/app/customers`) — searchable/filterable table, CSV import/export, click → **Customer profile** (`/app/customers/[id]`) with photo, contact, lifetime value, points, membership, AI churn-risk badge, visit history, points ledger, communication timeline, notes/tags.
- **Loyalty** (`/app/loyalty`) — config editor (points rules, expiry), points ledger explorer, manual-adjust dialog.
- **Rewards** (`/app/rewards`) — grid of reward cards, create/edit, redemption tracking.
- **AI Assistant** (`/app/assistant`) — ChatGPT-style chat UI wired to the AI module; suggested prompts ("Why are sales down?", "Who are my VIPs?", "Create a win-back campaign"). Shows live data-backed answers.
- **Dark mode** everywhere via `next-themes`.
- `lib/api` typed client (auto-generated types from shared package).

## Shared (packages/shared, packages/ui)
- `shared`: zod schemas + TS types mirroring Prisma models, role/enum constants, plan definitions, API response shapes. Imported by both apps.
- `ui`: shadcn primitives (Button, Card, Input, Dialog, Table, Badge, Avatar, Tabs, etc.) themed to brand, plus bespoke `KpiCard`, `StatChart`, `EmptyState`, `PageHeader`.

## What's explicitly OUT of scope this session (data model + stubs only)
Booking customer flow, QR check-in flow, multi-branch UI, campaign builder UI, Google review automation, admin panel, Stripe/Razorpay billing UI, staff management UI, WhatsApp/SMS/email actual sending, push notifications, customer mobile view (responsive web partially covers). DB tables exist; routes show placeholders.

## Execution order
1. Root scaffolding (pnpm workspace, turbo, tsconfig base, docker-compose, `.env.example`, README).
2. `packages/shared` + `packages/ui` (types + design system).
3. `apps/api`: Prisma schema → migrate/seed → auth + tenant guard → all modules → AI module.
4. `apps/web`: shell + auth + onboarding → dashboard → customers → loyalty → rewards → assistant → landing.
5. Wire web↔api, seed demo data, typecheck both apps, verify `turbo build` passes.
6. README with run instructions (Docker up DB → migrate → seed → run web+api).

## Verification bar before "done"
- `pnpm install` + `pnpm build` (turbo) succeeds.
- DB migrates and seeds without error.
- API: dashboard, customers, loyalty, rewards, AI endpoints return real data (tested via seed).
- Web: builds, dashboard renders real KPIs from API, customers CRUD works, assistant returns data-backed responses.
- Mock-auth path confirmed working with zero API keys; real-path documented.
